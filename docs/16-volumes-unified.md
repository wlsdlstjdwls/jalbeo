# 검색량 실측 4차 — 1차 품목 재측정과 정렬 기준 통일

> 2026-09-04. `docs/14`가 남긴 숙제의 마무리다.
> 결과: 154개 전 품목이 같은 자로 측정됐다. 미측정 0개.

## 무엇이 문제였나

1차 실측(`gate1-volumes.csv`)은 씨앗 실측이 아니라 연관어 덤프였다. 품목마다
우연히 걸린 어미가 달라서 합계의 기준이 제각각이었다.

```
이불   26,905 = 버리는방법 19,580 + 버리는법 3,140 + 버리기 2,380 + ...
선풍기 12,120 = 버리는법 12,120 (어미 1개만 걸림)
```

2차/3차는 `{품목}버리는법` + `{품목}분리수거` 두 어미만 씨앗으로 넣어 쟀다.
두 값을 한 컬럼에 놓고 정렬하면 순위가 뒤집힌다. 그래서 1차 품목을 2차의 자로
다시 쟀다.

## 어떻게 쟀나

- 묶음: `data/keywords/gate1-batches-4.md` (씨앗 174개, 35묶음)
- 원본: `data/keywords/gate1-4/*.xlsx` (네이버 키워드도구 다운로드, 35개)
- 집계: `scripts/gate1_batch4_aggregate.py` -> `data/keywords/gate1-volumes-4.csv`
- 병합: `scripts/merge_volumes.py` -> `data/keywords/volumes-merged.csv`,
  `db/publish_volumes_4.sql`

병합 우선순위는 4차 > 3차 > 2차다. 같은 어미가 여러 회차에 있으면 최신 회차를
쓴다. 안 걸린 어미는 0이 아니라 빈칸이다.

## 결과

품목 94개가 4차에서 다시 측정됐다. 같은 품목의 1차 합계 228,555가 4차 자로는
216,255다. 총량은 비슷해 보이지만 **품목별 이동폭이 크다** — 이게 재측정의 이유다.

|---|---:|---:|---:|

`docs/14`의 관찰(어미는 품목마다 뒤집힌다)이 1차 품목에서도 그대로 나왔다.
음식물 껍질류는 `분리수거` 어미가 압도적이라 1차 덤프에서 통째로 새고 있었다.
반대로 이불은 1차가 `버리는방법`까지 긁어 부풀어 있었다.

병합 후 154개 합계는 268,710이다.

## 어미 한쪽만 걸린 품목 11개

유리, 전자레인지, 소파, 밥솥, 컴퓨터, 킥보드, 소화기, 공기청정기, 정수기,
장롱, 전기장판.

이 중 4개(밥솥/소화기/전기장판/전자레인지)는 4차 씨앗에 넣었는데 키워드도구가
행 자체를 안 돌려줬다. 나머지는 회차 사이에 어미 한쪽만 씨앗에 들어갔다.
**빈칸은 0이 아니다.** 이 품목들의 합계는 걸린 어미만 더한 하한값이다.

## 반영

`db/publish_volumes_4.sql`을 items 테이블에 적용했고, `scripts/pull_items_db.py`로
`site/src/data/items.json` 스냅샷을 다시 떨궜다. `monthly_volume`이 null인 품목은
이제 없다. 홈 목록 정렬이 154개 전부 같은 자 위에 선다.

`scripts/pull_items_db.py`는 `site/scripts/pull-data.mjs`의 대역이다. 후자는
PostgREST(`SUPABASE_URL`/`SUPABASE_ANON_KEY`)를 쓰는데 이 환경엔 그 키가 없어서,
`db_apply.py`와 같은 세션 풀러로 붙어 같은 질의를 낸다. 정렬 기준도 같다.

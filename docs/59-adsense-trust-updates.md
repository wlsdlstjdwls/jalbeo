# 59. 애드센스 반려 대응, 업데이트 기록, 수수료 파일명 충돌

2026-10-02

## 반려

애드센스가 "가치가 별로 없는 콘텐츠"로 반려했다. 문구가 요구하는 것은 셋이다.
고유 가치, 꾸준한 운영, 사용자 관심. 본문 분량은 원인이 아니다 - 277개 중 가장
짧은 선반이 1,593자, 중앙값 3,420자다. 원인은 둘로 본다.

- **트래픽과 운영 기간.** 도메인 연결 한 달이 안 됐고 품목 착지 검색 유입이 2건이다
  (`docs/58`). 이건 페이지로 안 풀린다. 재신청은 1~2개월 뒤로 미룬다
- **유지관리가 겉에서 안 보인다.** 감사 기록이 전부 `docs/`에 있고, 품목 `updated`는
  9월 4~14일에 몰려 있었다. 밖에서는 18일째 멈춘 사이트다

## 한 것

- `/about/` 소개 페이지. 품목과 가이드 수는 컬렉션에서 센다. 문의처(운영자 Gmail)를
  개인정보처리방침 11항과 소개 페이지에 적었다. 푸터에 소개, 업데이트 기록 링크
- `/updates/` 업데이트 기록. 정정과 기능은 `site/src/lib/updates.ts`에 손으로 적고,
  품목 추가는 `scripts/build_added_dates.py`가 git에서 첫 커밋 날짜를 뽑아
  `site/src/lib/added.json`에 쓴다. 적는 기준은 docs에 기록이 있고 방문자 화면이
  실제로 바뀐 것. 내부 용어(별칭, 실측, 판단 N)는 안 쓴다
- 홈에 '최근 소식'(최근 고친 내용 3줄, 새 품목 8개)
- 수수료 표 아래에 마지막으로 받은 날. `build_fee_stats.py`가 `fees_meta.json`을 쓴다
  (manifest는 `site/` 밖이라 빌드가 못 읽는다)

## 수수료 재수집: 열린 이슈 #6과 파일명 충돌

데이터 최신성 체크가 9/21에 변경을 감지해 이슈 #6을 열었는데 아무도 안 봤다.
9/28 런은 GitHub 결제 문제로 시작도 못 했다(`The job was not started because recent
account payments have failed`). **사이트가 겉으로 멈춰 보였던 것과 같은 자리에서
실제 유지관리도 멈춰 있었다.**

이슈 내용은 기준일 갱신(함양, 대덕, 고령, 남광주)이라 수치 변화가 없었다. 그런데
로컬에서 다시 받으니 **오산시 220행이 통째로 사라졌다.** 원인은 파일명이다.
함안군, 오산시, 속초시가 셋 다 `대형폐기물 처리 수수료 정보.csv`로 내려오고
`fetch_fee_datasets.py`는 Content-Disposition 이름을 그대로 써서 뒤에 받은 속초가
앞의 둘을 덮어썼다. 오산이 이번에 파일명을 바꾸면서 드러났을 뿐이고, **함안군은
처음부터 한 번도 들어온 적이 없다.** 겹치면 dataset_id를 앞에 붙이게 고쳤다.

결과: 8,597행 47지역 -> 8,691행 48지역. 함안 95행 추가, 오산은 개정판 반영(1행 감소).
판단 43의 다른 얼굴이다 - 다운로드 수는 75로 멀쩡했고 실패도 없었다. 파일 수와
데이터셋 수가 같은지는 아무도 안 셌다.

- `check_fee_claims.py`가 27건 어긋남. 대부분 등재 수 +1(함안). 30개 페이지 정정,
  `updated`를 올렸다. '47개 시군구' 11곳을 48로
- 검사기의 `TOTAL_REGIONS = 47`이 손으로 박혀 있었다. 데이터에서 세게 바꿨다
- 함안이 들어오자 CD에 요금표가 생겼다. '카세트'(카세트 라디오) 3곳이 문턱 3을
  넘었다. CD 본체는 0건이다(판단 47). `EXTRA_ALIAS`에서 막았다
- 함안 품목표에 도어락, 훌라후프, 스타일러, 베개, 이사박스가 없어 '한 곳도 없다'
  문장들은 그대로 참이다

## 판단

94. **일을 하는 것과 일한 흔적이 보이는 것은 다르다.** 애드센스 심사자, 검색엔진,
    방문자는 `docs/`를 안 본다. 정정 기록을 방문자 문장으로 사이트에 내는 것이
    유지관리 신호이자 신뢰 신호다. 다만 날짜만 올리는 것은 조작이다 - `updated`는
    본문이 실제로 바뀐 페이지만 올린다

95. **자동 감시가 연 이슈를 아무도 안 보면 감시가 없는 것과 같다.** 최신성 체크는
    제대로 울렸고 결제가 막힌 것도 런 화면에 적혀 있었다. 세션 시작 때
    `gh issue list --label data-freshness --state open`과 최근 런 결론을 본다

96. **저장 이름이 겹치면 수집 성공 수가 거짓말을 한다.** 75건 받았다는 숫자는 맞았는데
    파일은 73개였다. 판단 43이 "0건이면 실패"였다면 이쪽은 "N건 받았는데 N개가
    아니다"다. 같은 지역 이름 없는 파일명을 쓰는 지자체가 셋이었다

- 홈 목록의 별칭 나열을 뺐고, 품목 페이지의 '로도 불립니다'는 앞 3개만 보인다.

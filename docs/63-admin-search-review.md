# 관리자 화면 검색어 후보, 로그인 정비

2026-10-12. `docs/62` 직후 사용자 요청 둘.

## 후보 뽑기를 관리자 화면으로

`search_log_candidates.py`를 손으로 돌려야 후보가 보였다. 처음에는 주간
GitHub Actions가 이슈를 띄우게 하려고 search_queries만 읽는 DB 계정까지
만들었는데, 사용자가 관리자 화면 버튼을 제안해 그쪽으로 바꿨다. 계정은
지웠다. 저장소가 public이라 리포 시크릿에 DB 계정을 두는 것보다 이미 있는
로그인과 `is_admin()` 판정을 쓰는 쪽이 열린 문이 적다.

`/admin/` 맨 아래 **못 찾은 검색 (90일)**, '후보 불러오기' 버튼.

- `admin_search_misses(p_days)` - hit_count = 0 행과 판정을 돌려준다 (`0010`)
- 화면이 스크립트와 같은 일을 한다. 같은 방문자 3분 안 앞토막 접기, 그리고
  **지금 어휘로 걸리는 말은 뺀다**(판단 71). 어휘는 빌드 때 items.json에서
  굽는다 - 발행하고 배포하면 그 검색어는 다음부터 저절로 빠진다
- 검색어가 품목명을 품는데 검색이 안 거는 경우('향수베이스'처럼)는
  "OO 페이지가 있는데 이 말로는 안 걸립니다. 별칭 후보"라고 붙인다
- 오타, 입력 조각, 보류처럼 어휘로 안 지워지는 것은 '보류', '노이즈' 버튼으로
  `search_term_decisions`에 적고 숨긴다. 되돌리기 가능.
  오늘 판정한 다섯(단호바교ㅣ, 휴대포, 믹싱, 밤송이 겉, 오징어)은 미리 넣었다
- 정렬은 사람 수, 횟수, 최근 순. 한 사람이 표기를 바꿔 다섯 번 친 것보다
  두 사람이 한 번씩 친 것이 위다

## 로그인

| 증상 | 원인 | 처리 |
|---|---|---|
| 비밀번호 저장 제안이 안 뜸 | 로그인 성공 직후 **비밀번호 칸을 비우고** 폼을 숨겼다. 브라우저는 폼이 사라질 때 값을 읽어 저장을 제안하는데 그 값이 이미 비어 있었다. `name` 속성도 없었다 | 칸을 안 비운다(로그아웃 때 비움). `name` 추가. 크롬, 엣지는 `PasswordCredential`로 저장을 직접 청한다 |
| 이메일을 매번 침 | 저장 안 함 | 마지막 로그인 이메일을 localStorage에 두고 채운다 |
| 로그인 누르면 칸이 간헐적으로 빨개짐 | `type=email required`의 브라우저 기본 검사. 한글 입력 상태로 친 글자, 자동완성이 값을 아직 안 넘긴 순간을 틀림으로 칠한다(파이어폭스는 빨간 테두리) | `novalidate`, 빈 칸 확인은 스크립트가 문구로 |
| 자꾸 로그아웃됨 | 화면 갱신 중 **네트워크 오류도** 세션을 지웠다. 노트북을 덮었다 열면 로그인부터 다시 | 서버가 갱신 토큰을 거절했을 때만 지운다. 네트워크 오류는 다음 주기에 다시 묻는다 |
| 서버 못 닿음도 "비밀번호가 맞지 않습니다" | 오류 종류를 안 갈랐다 | 응답 상태가 있을 때만 그 문구, 없으면 연결 문구 |

빨개지는 것은 재현을 못 했다. 원인은 위 둘 중 하나로 보고 기본 검사를 껐다.
Playwright로 API를 흉내 내서 빈 칸, 틀린 비번, 로그인 후 비번 유지, 이메일 기억,
후보 목록, 노이즈 저장(204 빈 본문)을 확인했다.

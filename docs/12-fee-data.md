## 컬럼 편차

지자체마다 컬럼명이 달라 별칭 표로 흡수했다.

- 품목: `대형폐기물명` `폐기물 명` `품목` `품명` `물품` `폐기물이름` `수거품목명`
- 수수료: `수수료` `금액` `단가` `부과금액` `처리비` `총수수료` `폐기수수료` `가격`
- 원본에 오타 표기가 그대로 있다 — `페기물품목`, `폐기물품병`

인코딩은 UTF-8, EUC-KR이 섞여 있어 순차 시도로 읽는다.

주의 — 자치구 이름이 2글자인 곳(`동구`, `서구`, `남구`)은 정규식 하한을 1로
두지 않으면 통째로 누락된다. 대구, 대전, 울산 720행이 이 문제로 빠졌다가 복구됐다.

## 품목 커버리지

발행 20개 중 **18개**에 수수료가 붙는다. DB 92개 기준 **74개(80%)**.

미커버 18개는 냄비, 건전지, 헌옷, 종이컵, 페트병, 음식물류로, 애초에 대형폐기물이
아니라서 수수료 데이터가 존재하지 않는 게 정상이다.

**러그만 예외** — 원본에 `카펫`(24) `카페트`(17) `카펫트`(9)로 등록돼 있다.
별칭 연결이 필요하다.

## 페이지 반영 (2026-09-03)

`scripts/build_fee_stats.py`가 품목별 통계를 내고 `site/src/data/fees.json`으로
주입한다. 20개 중 **19개**에 수수료가 붙는다 (계란껍질만 없고, 일반쓰레기라 정상).

매칭에서 조심한 것

- **접두 품목 오염** — 단순 부분일치면 `피아노`가 `전자피아노` 행까지 흡수한다.
  가장 긴 이름을 먼저 보게 해서 분리했다. 그 결과 전자피아노는 44지역
  13,000원(오염)에서 6지역 5,750원(실제)으로 정정됐다.
- **나열형 표기** — `비디오, 청소기, 정수기, ... 선풍기, 쌀통` 처럼 한 행에
  9개 품목이 묶인 경우가 있어 토큰으로 쪼갠 뒤 매칭한다.
- **묶음 접미** — `피아노류`, `카펫트류`는 `류`를 떼고 같은 품목으로 본다.
- **러그** — 원본에 `카펫`, `카페트`, `카펫트`로 등록돼 있어 별칭으로 연결했다.
  0지역에서 42지역이 됐다.
- `악기(피아노 제외)` 같은 표기는 매칭되지 않는다 (접미 일치라 통과 못 함).

표시 원칙 — 지역 편차가 크므로 단일 금액을 못 박지 않는다.

- 중앙값을 앞세우고 최저~최고와 사분위 구간을 막대로 보여준다
- 표본이 10개 지역 미만이면 "참고용" 경고를 붙인다 (전자피아노, 골프채)
- 최고가 최저의 2배 이상이면 배수를 밝히고 거주지 확인을 안내한다
- 출처 링크와 기준일자를 함께 표시한다 (CLAUDE.md 규칙)

## 본문 수치 대조 (2026-09-07 추가)

`FeeTable`이 `fees.json`을 읽어 화면에 지역 수와 중앙값을 띄우는데, 본문에도
같은 숫자를 손으로 적어 둔 페이지가 많다. 데이터를 다시 내도 본문은 안 따라오니
둘이 어긋난다. 실제로 **28건이 어긋나 있었다** (`docs/25` 6번).

가장 흔한 형태는 **행 수를 시군구 수로 적는 것**이다. 수집한 시군구는 47개뿐인데
"105개 시군구"라고 적힌 페이지가 있었다. 한 시군구가 규격별로 여러 행을 갖는다.

```
python scripts/check_fee_claims.py    # 어긋나면 exit 1
```

수수료를 재수집하거나 `build_fee_stats.py`를 다시 돌린 뒤에는 이걸 돌린다.

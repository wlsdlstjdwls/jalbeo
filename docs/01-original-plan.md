# 최초 기획안 (원문 보존)

> 2026-09-03 작성. 검토 전 원안. 변경 사항은 `02-review.md` 참조.

## 포지션

"품목 × 지역" 조합 웹페이지로 롱테일 검색어 공략.
블리스고(전국 공통 정보만) / 여기로·빼기(신고 도구) 사이의 빈 틈.

## 타깃 검색어 예시

- 매트리스 버리는법 용산구
- TV 폐기 수수료 세종시
- 건전지 어디에 버려요
- 치킨뼈 음식물쓰레기

## 페이지 구조 (2층)

### A. 품목 페이지 (전국 공통, 허브)

- 음쓰/일쓰/재활용 O·X 판별을 최상단에 크게
- 이유 + 예외 케이스 + 헷갈리는 유사 품목 링크
- 목표 500~800개 (건전지, 형광등, 아이스팩, 옷걸이, 프라이팬…)

### B. 대형폐기물 페이지 (품목 × 지자체)

- 수수료 / 신고 방법 / 스티커 구매처 / 배출 요일
- 대형폐기물 품목 약 100개 × 지자체
- 전체 226개 지자체는 무리 → 서울 25개구 + 수도권 주요 시부터
- 초기 목표: 100 × 30 = 3,000페이지

## 데이터 소스 (착수 전 확인)

1. 공공데이터포털 — 대형폐기물 수수료 데이터 개방 여부 ← 여기부터
2. 각 지자체 조례 (자치법규정보시스템)
3. 환경부 분리배출 가이드라인 — 품목 페이지 기초 데이터

3번은 공개돼 있어 쉬움. 1번이 없으면 지자체별 크롤링이라 난이도가 확 오름 → 결과에 따라 지역 범위 조정.

## 기술 스택

- Spring Boot + MariaDB, EC2
- SSR 필수 (Thymeleaf 등) — SPA면 크롤링에 불리
- sitemap.xml 자동 생성, 구조화 데이터(JSON-LD)
- 본문은 Claude로 생성하되 템플릿 티 안 나게 품목별 변주

## 진행 순서

1. 데이터 소스 확인 (반나절)
2. 도메인 + 뼈대 (주말 1회)
3. 품목 페이지 100개 먼저 배포 → 색인 상태 확인
4. 색인 정상이면 대형폐기물 지역 페이지 확장
5. 애드센스는 트래픽 붙고 나서

## 전제

- 유입 발생까지 6개월 이상
- 수익 기대치는 월 수십만 원 레벨

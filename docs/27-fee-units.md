# 과금 단위 — 면적, 길이, 무게를 데이터에서 가른다

> 2026-09-07. `docs/12`가 남긴 숙제다. 장롱 '1쪽당'은 그때 처리했지만
> 나머지 단위는 통짜 요금과 한 통에 섞여 있었다. 폐목재 '5kg당'을 본문으로만
> 때운 것도 그래서였다.

## 문제

`fees.csv` 8,649행 중에 값이 **한 개당**이 아닌 행이 섞여 있다.

```
장판   | 3.3㎡당      2,000원
장판   | 5m당         2,000원
카펫   | 3.3㎡ 당     5,000원
깨진 유리, 항아리 | kg당  1,000원
인형+장난감류 | 소형(3㎏당) 1,000원
폐목재류 | 5㎏당       1,000원
```

`build_fee_stats.py`는 '쪽당'만 따로 빼고 나머지를 전부 `whole`에 넣고 있었다.
그래서 장판의 중앙값 2,000원에는 **3.3㎡ 값과 통짜 값이 같이** 들어가 있었다.
방 네 평을 걷어낸 사람은 8,000원을 내는데 화면은 2,000원이라고 말한다.

## 규격 구간과 과금 단위를 구별해야 한다

처음에 단위 후보를 넓게 잡았더니 냉장고가 걸렸다. `300ℓ 이상`, `18평형`,
`1m 이상` 같은 표기는 **크기 구간**이지 과금 단위가 아니다. 냉장고 125행,
에어컨 75행이 이런 오탐이었다.

구별선은 하나다. **'당'이 붙었는가.** 구간 표기는 이상, 미만, 이하로 끝나고
과금 단위는 당으로 끝난다. 그래서 정규식이 수량과 단위를 잡되 뒤에 '당'을
요구한다.

```python
("weight", "kg", r"(\d+(?:\.\d+)?)?\s*(kg|㎏|킬로그램|킬로|톤|t)\s*당", {"톤": 1000}),
("area",   "㎡", r"(\d+(?:\.\d+)?)?\s*(㎡|m2|제곱미터|평)\s*(?:\([^)]*\))?\s*당", {"평": 3.3}),
("length", "m",  r"(\d+(?:\.\d+)?)?\s*(m|미터|cm|㎝)\s*당", {"cm": 0.01}),
```

## 기준 단위로 환산한다

단위를 가르는 것만으로는 부족했다. **같은 면적 단위 안에서도 1㎡당과 3.3㎡당이
섞여 있다.** 그대로 중앙값을 내면 그 안에서 또 3.3배가 틀린다.

그래서 수량을 파싱해 기준 단위(㎡, m, kg)로 나눈 뒤에 담는다. `3.3㎡당 2,000원`은
`1㎡당 606원`이 되어 `1㎡당 2,000원`인 지자체와 같은 자리에 놓인다. '평'은 3.3㎡,
'톤'은 1,000kg, 'cm'는 0.01m로 환산한다.

## 결과

빼면 그만큼 줄어야 한다.

## 화면

`fees.json`이 `whole`, `panel` 두 칸에서 다섯 칸으로 늘었다. `primary`는
지역 수가 가장 많은 단위이고, 같으면 통짜가 앞이다.

`FeeTable.astro`는 이제 단위 이름을 데이터에서 받는다. 단위당 요금은 하나만
보면 감이 안 오므로 흔한 크기를 곱해 같이 보여준다 — 쪽당은 3쪽, 면적은
3.3㎡(1평), 길이는 5m, 무게는 10kg. 나머지 단위는 아래에 한 줄씩 붙는다.

```
3,000원 전후
19개 지자체 공개 요금의 중앙값입니다.
15곳은 1㎡당으로 부과하며 중앙값 606원입니다.
7곳은 1m당으로 부과하며 중앙값 400원입니다.
```

## 본문

숫자가 바뀐 페이지 9개를 고쳤다. `check_fee_claims.py`가 전부 잡아 줬고,
표 안의 `| 19곳 |` 같은 표기도 검사하도록 패턴을 하나 더 붙였다. 검사 건수
111건 -> 119건.

장판, 유리, 러그, 거울은 단위 비교표를 본문에 넣었다. 이 품목들은 **단위를
모르면 신고 화면에서 수량 칸을 못 채운다.** 값보다 단위가 먼저인 품목이다.

## 남은 것

폐목재(5kg당)와 나뭇가지는 무게 단위 행이 3지역을 못 채워 데이터가 없다.
본문에만 남아 있다. 표본이 늘면 자동으로 들어온다.

부피 단위(100ℓ 마대당, 자루당)는 아직 `whole`로 들어간다. 마대 자체가
지자체마다 규격이 달라 환산 기준이 없다. 장판 본문에서 문장으로만 다룬다.

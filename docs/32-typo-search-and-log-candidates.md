# 오타 검색과 검색어 로그 후보 (2026-09-07)

도메인 연결 뒤 처음으로 사람이 친 검색이 로그에 남았다. 그중 하나가 오타였고,
오타는 페이지로 받을 수 없다. 검색이 받아야 한다.

## 1. 로그에 뭐가 들어왔나

`python scripts/search_log_candidates.py --all`

```
검색 로그 19건 / 방문자 2명   기간 2026-09-04 ~ 2026-09-07
디바운스 조각 4건 접고 15건, 그중 못 찾은 검색 10건
```

표본 기준(방문자 10명, 못 찾은 검색 20건)에는 한참 못 미친다. `docs/23`
선례대로 **빈도를 수요로 읽지 않고**, 발행 품목과 안 겹치는 것만 개별로 본다.

| 검색어 | 판정 | 처리 |
|---|---|---|
| 닌텐도, 플스, 플레이스테이션 | 신규, 세 표기가 한 답(게임기) | 실측 10차 |
| 피규어 | 신규 | 실측 10차 |
| 팬티 | 신규, 헌옷과 답이 갈릴 수 있다 | 실측 10차 |
| 오징어 | 신규, 음식물 축 | 실측 10차 |
| 썬크 | 화장품 별칭 '선크림'은 있는데 '썬크림'이 없다 | 별칭 추가 + 실측 |
| 공기청덩 | **오타.** 공기청정기 페이지가 이미 있다 | 검색이 받는다 (아래) |
| 침대커버 | 침대(대형폐기물)로 잘못 걸린다 | 보류 - 조사가 먼저다 |
| 매니, 안경, 의자, 방충망, 캣타워, 공기청정기 | 이미 걸린다 | 없음 |

`침대커버`를 보류한 이유는 검색량이 아니라 답이다. 이불(대형폐기물)로 가는지
헌옷(의류수거함)으로 가는지가 갈리고, 지금은 엉뚱하게 침대 페이지가 뜬다.
표본 1건이니 조사 순서를 앞당길 근거도 없다.

## 2. 오타는 페이지가 아니라 검색이 받는다

`공기청덩`은 페이지를 낼 대상이 아니다. 별칭으로 넣을 것도 아니다 - 오타
경우의 수만큼 별칭을 심으면 그게 곧 잡음이다. 검색이 한 글자 어긋남을
견디게 만드는 것이 맞다.

### 왜 안 걸렸나

검색은 `data-key` 한 줄에 대한 부분일치(`indexOf`) 하나뿐이었다. 별칭, 초성,
로마자, 공백무시까지 다 받지만 **한 글자라도 어긋나면 0건**이다.

### 음절이 아니라 자모로 잰다

음절째로 편집거리를 재면 `정`과 `덩`이 거리 1이고 `정`과 `청`도 거리 1이다.
초성 하나 틀린 오타와 아예 다른 낱말이 같은 값이 된다. 자모로 풀면
`공기청덩` = `ㄱㅗㅇㄱㅣㅊㅓㅇㄷㅓㅇ`으로 11자가 되고, 그중 1자만 다르다.
길이가 길어지는 만큼 **임계값을 글자수에 비례해 줄 수 있다.**

```
자모 9자 이상 -> 2까지 봐준다
자모 5자 이상 -> 1까지
그 미만       -> 안 봐준다
```

짧은 말에 1을 주면 안 되는 이유가 있다. `플스`(자모 4)에 1을 주면 아무
품목에나 걸리고, 그 순간 **'못 찾은 검색'이라는 신호가 사라진다.** 품목 확장
후보는 hit_count = 0에서 나온다 (`docs/20`).

### 앞토막을 벌하지 않는다

편집거리 DP의 첫 행을 0으로 두면 부분일치가 된다. 검색어는 대개 이름의
앞토막이다 - 디바운스 때문에 `냉장꼬`까지만 들어오고 `냉장고문짝`은 안
들어온다. 꼬리를 벌하면 그런 질의가 다 떨어진다.

### 정확히 0건일 때만 돈다

부분일치가 하나라도 있으면 오타 판정을 아예 돌리지 않는다. 정상 검색의
결과와 속도가 그대로다. `이불`을 오타 허용으로 재면 충전기, 전선, 밥상까지
6건이 뜨는데, 부분일치가 이미 2건을 주므로 그 경로로 안 들어간다.

### 로그에 쏘는 값은 오타 구제 이전 개수다

`lastShown = exact`. 오타로 구제된 건수를 hit_count에 넣으면 hit = 0이던
검색이 hit = 1이 되어 확장 후보에서 사라진다. 화면은 구제하고 로그는 그대로
0을 적는다.

### 실제 확인 (astro preview + playwright)

| 친 말 | 결과 |
|---|---|
| 공기청덩 | 공기청정기 |
| 냉장꼬 | 냉장고, 김치냉장고 |
| 형과등 | 형광등 |
| 전자렌지 | 전자레인지 |
| 텔레비젼 | TV |
| 썬크림 | 화장품 |
| 플스, 닌텐도 | 0건 (짧아서 안 봐준다 - 신호 보존) |
| 소파, 이불 | 부분일치 그대로, 오타 판정 안 탐 |

오타로 구제된 결과는 머리말이 `혹시 이걸 찾으셨나요`로 바뀐다. 정확히
맞은 결과와 구분되어야 사용자가 다른 품목의 답을 자기 것으로 읽지 않는다.

### 코드가 두 군데다

`site/src/lib/search.ts`의 `jamo`, `normalize`를 인라인 스크립트가 다시
쓴다. `define:vars` 스크립트는 인라인이라 모듈을 import 할 수 없다.
한쪽을 고치면 다른 쪽도 고쳐야 한다 - 주석으로 박아 뒀다.

## 3. 별칭 1건

화장품 aliases에 `썬크림`을 넣었다 (`db/apply.sql`). `선크림`은 이미 있었다.
오타가 아니라 둘 다 쓰이는 표기라 별칭이 맞다.

**함정:** `array(select distinct unnest(aliases || array['썬크림']))`으로
넣었더니 순서가 흐트러졌다. 별칭은 화면에 그 순서로 노출된다. 배열을 손으로
다시 적어 되돌렸다.

## 4. 실측 10차 묶음 준비 (사용자 실행 대기)

`scripts/build_searchlog_batch.py` -> `data/keywords/gate1-batches-10.md` + html
5주제 18키워드 4묶음. xlsx를 `data/keywords/gate1-10/`에 넣고
`python scripts/gate1_batch10_aggregate.py`.

**9차와 다른 점: 하한선 판정이 없다.** 품목 축에는 하한선이 없다 - 발행된
167개 중 러닝머신 20, 보일러 20이 있다. 그러니 이 실측은 발행 여부를 안
정한다. 정하는 것은 둘이다.

- 어느 표기를 페이지 이름으로 쓸까 (두 어미 합계 1위, 판단 11번)
- 나머지 표기는 별칭인가 분리인가 (본체의 2배가 경계, 판단 12번)

발행 여부는 **답이 기존 페이지와 갈리는지**로 따로 답한다. 게임기가 폐가전
페이지들과 같은 답을 한다면 검색량이 커도 페이지를 늘리면 안 된다 (판단 5번).

## 5. 실측 10차 결과 (같은 날 도착)

사용자가 키워드도구 4묶음을 돌려 `data/keywords/gate1-10/`에 넣었다.
`python scripts/gate1_batch10_aggregate.py` -> `gate1-volumes-10.csv`.

| 주제 | 표기별 두 어미 합계 | 처리 |
|---|---|---|
| 속옷 | **속옷 1,550** / 팬티 110 | **페이지 발행** |
| 피규어 | 90 | 장난감 별칭 |
| 게임기 | 게임기 35 / 플스 20 / 플레이스테이션 20 / 닌텐도 20 | 보류 |
| 썬크림 | 35 | 화장품 별칭 (위에서 이미 넣었다) |
| 오징어 | 20 | 보류 |

### 속옷을 페이지로 낸 이유

검색량이 아니라 **답이 갈려서**다. 헌옷 페이지(585)를 열어 보니 속옷을 한
글자도 안 답하고 있었다. 그런데 속옷은 1,550으로 헌옷의 2.6배다 -- 판단
12번이 말하는 "별칭을 붙이면 그 단어의 수요가 안 보인다"의 전형이다.

조사에서 나온 사실 하나가 페이지의 뼈대가 됐다. **지자체 목록에 속옷이라는
이름이 아예 없다.** 관악구, 연수구, 성동구 셋 다 받는 목록에도 안 받는
목록에도 안 적었다. 판단 22번(목록에 이름이 없으면 그 표로 답하지 않는다)의
반대편 경우다 -- 이름이 없으니 목록이 아니라 기준으로 답해야 한다. 훈령
별표1의 의류 비해당 문구("해지거나 오염되어 다시 사용할 수 없는 의류와
잡화")가 그 기준이고, 선은 재사용 여부다.

`db/publish_168.sql`. verdict는 `조건부`, 검색량 1,550, 별칭은 팬티,
브래지어, 브라, 내복, 런닝셔츠.

### 게임기와 오징어를 보류한 이유

게임기 축은 검색어 로그에 세 건(닌텐도, 플스, 플레이스테이션)이 찍혀 이번
회차에서 제일 굵은 신호였는데, 재 보니 표기를 다 합쳐도 95다. 그리고 답이
소형 전기전자제품(5개 이상 모으거나 전용수거함)이라 멀티탭, 충전기,
에어프라이어 페이지와 같다. **판단 5번대로 같은 답을 하는 페이지를 늘리지
않는다.** 별칭도 아니다 -- 게임기는 그 품목들과 다른 물건이라 별칭으로
붙이면 오답이 된다. 수요가 커지면 그때 낸다.

오징어(20)는 음식물 축이고, 판단 7번대로 음식물은 수요가 작다.

### 침대커버는 별칭이 됐다

조사해 보니 답이 이미 이불 페이지에 있었다 -- <strong>"커버류(이불커버,
베개커버)는 벗겨서 세탁하면 수거함에 넣을 수 있습니다"</strong>. 관악구
수거대상 목록에도 베개커버, 이불커버가 이름째로 실려 있다. 답이 있는데
검색만 침대(대형폐기물)로 잘못 걸리고 있었으므로 별칭이 맞다.
`침대커버`, `이불커버`, `침대시트` 셋을 이불에 붙였다.

# 데이터 최신성 체크 오탐 차단, 수수료 재수집 반영

2026-09-07. 깃헙 이슈 "수수료/훈령 데이터 변경 감지 2026-09-07"(#3)이 올라왔다.
`fees.csv` 8,649행 전부 삭제라는 diff였다. 오탐이었고, 막고 나니 같은 워크플로가
진짜 변경(#4)을 잡았다. 둘 다 이 문서에서 처리했다.

## 오탐의 경로

`.github/workflows/data-freshness-check.yml`은 매주 수수료(data.go.kr)와
훈령(law.go.kr)을 다시 받아 커밋본과 다르면 이슈를 연다. 이번 실행 로그는
이랬다.

```
[1/3] 데이터셋 목록 수집
  ! <urlopen error timed out>
  총 0건
완료 — 성공 0 / 실패 0
총 0행 / 지역 0 / 고유 품목 0
```

1. data.go.kr이 러너(해외 IP)에 응답을 안 줬다. 목록 0건인데 fetch가 exit 0
2. `data/raw/fees/*.csv`는 gitignore라 러너에는 manifest.json만 있다. fetch가
   그걸 빈 목록으로 덮어썼다
3. normalize가 CSV를 하나도 못 찾고 `fees.csv`를 헤더만 남겼다. exit 0
4. diff 단계가 8,649행 삭제를 "변경"으로 읽어 이슈를 열었다

훈령 쪽도 law.go.kr 5회 전부 타임아웃이었지만 `continue-on-error`라 파일을
안 건드렸다. 수수료 쪽만 빈 결과를 정상 산출물로 썼다.

## 막은 곳 (df4899b)

- `fetch_fee_datasets.py`: 목록 0건 또는 다운로드 0건이면 manifest를 안 쓰고 exit 1
- `normalize_fees.py`: 유효 행 0건이면 `fees.csv`를 안 쓰고 exit 1
- `fetch_env_guidelines.py`: 훈령 3건 중 하나라도 못 받으면 manifest를 안 쓰고 exit 1
- 워크플로: 다운로드 수가 커밋본의 90% 미만이면 "수집 불완전"으로 잡을 실패시킨다.
  훈령 단계가 실패하면 훈령 파일은 diff 대상에서 뺀다

실패는 이슈가 아니라 잡 실패로 남는다. **접속 실패와 데이터 변경은 다른 사건**이고
전자를 후자로 보고하면 사람이 diff를 읽다가 지친다. 로컬 시뮬레이션 4경로(목록
0건, 다운로드 0건, raw CSV 없음, 훈령 미수집)가 전부 exit 1로 끊기고 파일을 안
건드리는 걸 확인했다. 정상 경로는 8,649행 그대로, diff 0줄.

## 막고 나니 진짜가 잡혔다 (#4, 01ac558)

수동 실행에서 data.go.kr이 응답했고 두 데이터셋이 바뀌어 있었다.

| 데이터셋 | 변화 |
|---|---|
| 경기도 양주시 (15148661) | 208행 -> 156행. 39개 품목 삭제, 10개 개명. 원본 CSV 자체가 156행(기준일 2026-08-04) |
| 부산 동구 (15116293) | 기준일 2025-08-26 -> 2026-08-18. 침대 2인용 20,000 -> 15,000 |

양주시가 뺀 품목이 자전거, 휠체어, 파라솔, 돗자리, 쓰레기통, 카펫, 이불, 장난감,
금고, 가방, 옷걸이, 변기, 방충망, 유모차, 카시트, 재봉틀, 빨래건조대, 커튼 등이다.
`fees.json`에서 26개 품목의 등재 수나 중앙값이 움직였고, 그중 14개 페이지가 본문에
숫자를 적고 있어 24군데를 고쳤다. 휠체어와 블라인드는 양주시를 예로 든 문장도
지웠다. 나머지 12개는 표 컴포넌트만 써서 손댈 게 없었다.

## 검사기가 놓친 모양

`check_fee_claims.py`는 "| 통짜 한 건 | 25곳 | **2,500원** |"에서 25곳은 잡고
2,500원은 안 봤다. 돗자리(2,500 -> 2,750)와 러그(5,000 -> 5,250)가 그렇게
새고 있었다. '통짜 한 건' 행과 단위 행(1㎡당, 1m당, 1kg당)의 중앙값 패턴을
추가했다. 170 -> 182건 검사, 어긋남 0.

## 로컬에서만 나는 함정

로컬 `data/raw/fees/`에 manifest에 없는 고아 CSV가 둘 있었다. 데이터셋 파일명이
바뀐 양주시 옛 파일과 광진구 "(2)" 중복 다운로드다. normalize가 그걸 읽어 지역
빈칸 행 586개를 섞었고 로컬 행 수(9,183)가 러너(8,597)와 달랐다. 지우니 같아졌다.
**재수집 뒤 행 수가 이슈 본문과 다르면 데이터가 아니라 고아 파일을 먼저 본다.**

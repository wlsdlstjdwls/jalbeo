# 게이트 2 폐기 — 색인 판정을 관문에서 내린다

> 기준일 2026-09-04. `docs/06` 7번을 대체한다.

## 무엇이었나

게이트 2는 "파일럿 20페이지를 배포하고 2~4주 색인 상태를 본 뒤,
색인되면 확장한다"였다. 목적은 하나다. 프로그래매틱 SEO가 구글의
scaled content abuse 판정을 맞으면 페이지를 몇 개 늘리든 트래픽이 0이니,
적은 수로 먼저 찔러보고 판돈을 키우자는 안전장치.

## 왜 폐기하나

**설계가 이미 무효다.** 관문을 통과하기 전에 154개를 발행했다.

| 게이트 2 설계 | 실제 |
|---|---|
| 품목 20개 배포 | 품목 154개 + 가이드 3개 발행 |
| 색인 확인 후 확장 | 확인 전에 6차 확장까지 진행 |

"적게 찔러본다"는 성질이 사라졌으므로, 남은 것은 파일럿 테스트가 아니라
157페이지짜리 색인 판정 한 번이다. 그건 관문이 아니라 그냥 결과 관측이다.

**게이트가 남아 있으면 나머지가 얼어붙는다.** 작업 규칙의
"게이트 통과 전 페이지 대량 생성 금지"가 걸려서, 색인 확인 전에는
실측도 가이드 확장도 명분이 없어진다. 그런데 색인 확인은 도메인 연결에
묶여 있고(아래), 도메인은 마지막 순서다. 통과할 수 없는 관문이
앞을 막고 있는 상태다.

## 색인 확인은 도메인에 묶여 있다

`site/src/lib/site.ts`의 `PRODUCTION_HOST = 'jalbeo.com'`이고,
`site/src/pages/robots.txt.ts`는 그 호스트가 아니면 `Disallow: /`를 뱉는다.
미리보기 배포(`*.vercel.app`)가 먼저 색인되어 판정이 오염되는 것을 막는
장치다. 즉 **도메인 연결이 색인의 시작 버튼**이고, 그 전에는 색인이
시작조차 하지 않는다. 이 동작은 그대로 둔다.

## 바뀌는 것

- 게이트 2는 중단 기준에서 내린다. 색인 실패가 프로젝트 중단 사유가 아니다
- "게이트 통과 전 대량 생성 금지" 규칙은 게이트 1까지로 한정한다
- 색인 여부는 도메인 연결 이후 관측 항목으로 옮긴다. 결과에 따라
  대응(본문 보강, 페이지 축소, 축 이동)을 정하되 확장 자체를 잠그지 않는다

## 바뀌지 않는 것

- **scaled content abuse 리스크는 그대로다.** 관문을 없앤 것이지 위험을
  없앤 것이 아니다. "같은 답을 하는 페이지를 늘리지 않는다"와
  "본문은 품목마다 직접 조사해서 쓴다"는 규칙이 이제 유일한 방어선이다
- robots.txt의 도메인 게이팅, 미리보기 색인 차단

# 도메인 연결, 색인 개방, 검색엔진 등록

> 2026-09-07. `docs/15`에서 게이트 2를 폐기하며 "색인은 도메인 연결 이후의
> 관측 항목"으로 미뤄둔 그 연결을 했다. 도메인은 `jalbeo.com`이다.
> 연결 자체는 30분이면 끝났는데, **연결한 뒤에도 사이트 전체가 색인 차단 상태로
> 떠 있었다.** 그 원인이 이 문서의 본론이다.

## 결론 먼저

1. **`jalbeo.com` 등록, 연결 완료.** `docs/05`가 2026-09-03에 추천한 그 도메인이
   나흘 뒤에도 미등록이라 그대로 샀다. `.kr`은 안 샀다
2. **도메인을 붙였는데 사이트가 통째로 `noindex`였다.** Vercel 환경변수
   `SITE_URL`이 `https://jalbeo.vercel.app`으로 남아 있었고, 그 값이
   `astro.config.mjs`의 기본값 `https://jalbeo.com`을 이겼다
3. **환경변수를 지워도 이미 나간 배포는 안 바뀐다.** 지운 뒤 재배포해야 반영된다.
   지웠다는 것과 반영됐다는 것은 다른 사건이다
4. **서치콘솔의 "사이트맵을 읽을 수 없음"은 사이트맵 문제가 아니었다.**
   차단 상태에서 제출해 구글이 `Disallow: /` robots를 캐시한 것이다.
   고칠 파일이 없고 기다리는 것이 답이다

## 1. `.com`이냐 `.kr`이냐

`docs/05` 조사일이 2026-09-03이라 등록 직전에 Verisign RDAP로 다시 쟀다.
후보 8개 전부 404, 즉 미등록 그대로였다. `jalbeo.com`을 샀다.

`.kr`을 안 산 이유는 가격이 아니다.

| | 판단 |
|---|---|
| 지역 신호 | `.kr`의 이점인데 이 사이트엔 필요 없다. 한국어 본문 167개면 구글이 지역을 판단할 신호가 이미 넘친다 |
| 갱신가 | `.kr`은 국내 등록대행에만 묶인다. `.com`은 나중에 원가 등록기관으로 이전할 수 있다 |
| 되돌릴 수 없음 | 연 차액은 몇천 원인데 도메인을 바꾸면 색인을 다시 쌓아야 한다. 차액이 판단 근거가 될 수 없다 |

`.kr`은 공개 RDAP가 없어 가용성을 확인하지 못했다. 확인할 필요도 없어졌다.

DNS는 가비아에 두고 Vercel이 준 레코드를 넣었다. apex는 A 레코드(216.198.79.1),
`www`는 CNAME이다. `www`와 `jalbeo.vercel.app` 둘 다 apex로 301을 걸었다.

## 2. 환경변수가 코드의 기본값을 이긴다

연결 직후 실제로 나가는 것을 재 봤더니 이랬다.

```
canonical      https://jalbeo.vercel.app/     <- 도메인이 아님
meta robots    noindex, nofollow              <- 176페이지 전부
robots.txt     User-agent: *  Disallow: /     <- 사이트 전체 차단
sitemap        https://jalbeo.vercel.app/...  <- 도메인이 아님
```

같은 커밋을 로컬에서 빌드하면 전부 `jalbeo.com`으로 정상이었다. 코드가 아니라
빌드 환경의 문제다. `astro.config.mjs`는 이렇게 생겼다.

```js
const SITE = process.env.SITE_URL ?? 'https://jalbeo.com';
```

기본값이 정식 도메인이라 "도메인을 붙이면 저절로 열린다"고 착각하기 쉽다.
실제로는 `??`의 왼쪽이 이긴다. Vercel에 `SITE_URL=https://jalbeo.vercel.app`이
남아 있었고 그게 기본값을 덮었다.

이 값은 도메인 연결 전에 `jalbeo.vercel.app`이 먼저 색인되는 것을 막으려고
넣어둔 것이다(`docs/15`). 역할이 끝났는데 지우는 절차가 없었다.

### 판정 기준이 요청 호스트가 아니라 빌드 시점 값이다

`lib/site.ts`의 `isProductionHost()`를 `Base.astro`와 `robots.txt.ts`가 함께
쓰는데, 둘 다 넘기는 인자가 `Astro.site`다. 이건 요청이 어느 호스트로 들어왔는지가
아니라 **빌드할 때 확정된 값**이다.

그래서 이 구조는 두 방향으로 다 어긋난다.

- `SITE_URL`이 vercel.app이면 -> `jalbeo.com`으로 들어와도 차단된다 (이번 사고)
- `SITE_URL`이 없으면 -> `jalbeo.vercel.app`으로 들어와도 열린다 (막으려던 것)

정적 사이트라 빌드 산출물이 하나뿐이니 호스트별로 다르게 낼 방법이 없다.
지금은 301로 vercel.app을 apex로 보내서 덮었다. 구조 자체는 그대로다.

### 지운 것과 반영된 것은 다른 사건이다

환경변수를 지운 뒤에도 실측값이 그대로였다. Vercel은 환경변수 변경으로 재배포를
걸지 않는다. 빈 커밋을 밀어서 새 빌드를 태우고 나서야 바뀌었다.

```
canonical      https://jalbeo.com/                  OK
meta robots    없음 (품목 페이지도 확인)             OK
robots.txt     Allow: /  +  Disallow: /admin        OK
sitemap        jalbeo.com/sitemap-0.xml, 175개      OK
admin          noindex + 사이트맵 제외              OK
www            301 -> jalbeo.com                    OK
vercel.app     301 -> jalbeo.com                    OK
```

사이트맵 175개는 발행 176페이지에서 `/admin/`을 뺀 수다.

## 3. 검색엔진 등록

네이버 서치어드바이저 소유확인은 메타 태그 방식을 썼다. `Base.astro`에 넣어
176페이지 전부에 나간다. 홈에만 있으면 되지만 위치를 분기하면 나중에 홈 레이아웃을
건드릴 때 사라진다.

확인이 끝나도 이 태그는 지우지 않는다. 네이버가 주기적으로 다시 본다.
그 이유를 주석으로 같이 박아 뒀다.

### 사이트맵 파일명

`@astrojs/sitemap`의 기본 산출물은 `sitemap-index.xml`이다. 사이트맵 프로토콜은
파일명을 정하지 않으므로 규격 위반이 아니고, robots.txt가 위치를 알려준다.

다만 `/sitemap.xml`을 먼저 찔러보는 도구가 흔해 404가 났다. `vercel.json`에
`/sitemap.xml -> /sitemap-index.xml` 리다이렉트를 붙였다.

### "사이트맵을 읽을 수 없음"

서치콘솔이 이렇게 떴다. 사이트맵을 전부 검증했는데 문제가 없었다.

```
HTTP 200,  Content-Type: application/xml,  BOM 없음
XML 파싱 OK,  loc 175개 전부 https://jalbeo.com/
Googlebot UA로 요청해도 200 (봇 차단 아님)
```

원인은 **구글의 robots.txt 캐시**다. 구글은 robots.txt를 약 24시간 캐시한다.
2절의 차단 상태(`Disallow: /`)일 때 사이트맵을 제출했으므로, 파일이 그 뒤에
고쳐졌어도 구글은 자기가 캐시한 "전부 차단"을 보고 사이트맵을 못 가져간다.

**고칠 파일이 없다.** 재제출 버튼을 반복해 눌러도 캐시가 만료되기 전엔 같은
결과다. URL 검사에서 색인 생성을 요청하면 robots 재조회를 앞당길 수 있다.

색인 개방 직후에 뜨는 서치콘솔 오류는 대체로 이 부류다. 파일을 의심하기 전에
**차단 상태에서 제출한 적이 있는지**를 먼저 본다.

## 남은 것

- **색인 관측.** `docs/15`가 게이트에서 관측 항목으로 내린 그것. 이제 시작된다
- **검색어 로그.** `docs/20`, `docs/23`. 트래픽이 없어 표본이 얇았다.
  도메인이 붙었으니 이제부터 쌓이는 것이 진짜 확장 원천이다
- **`isProductionHost` 구조.** 빌드 시점 값으로 판정하는 한 호스트별 분기는
  안 된다. 301로 덮어 뒀고 당장 고칠 이유는 없다
